************* Design YouTube Comments *******************************

Interview Question: Design the frontend architecture for a YouTube-like comment system.

The interviewer isn't primarily asking you to build the UI. They want to know how 
you'd design a comment system that can handle:
            Thousands of comments
            Nested replies
            Likes
            Sorting
            Pagination
            Adding/deleting comments
            Real-time updates
            Loading states
            Performance

1. First clarify the requirements:
----------------------------------
    In an interview, don't immediately start writing components.

    Start by asking: "Should I focus only on the frontend architecture, or should I also discuss backend/API design?"

    Assuming we're designing the frontend, I'd define the requirements.

    ->Functional requirements
      -----------------------
        Users should be able to:
                                View comments
                                Add a comment
                                Edit their comment
                                Delete their comment
                                Like/unlike comments
                                Reply to comments
                                View nested replies
                                Sort comments
                                Load more comments
                                See comment counts
                                See loading/error states
    
    ->Non-functional requirements
      ---------------------------
        The application should:
                                Remain responsive with thousands of comments
                                Avoid unnecessary API calls
                                Avoid unnecessary React re-renders
                                Support mobile and desktop
                                Handle network failures gracefully
                                Be accessible

2. Think about the UI:
----------------------
    A simplified YouTube comment section could look like:
                                            Comments
                                        ────────────────────────────

                                        [Write a comment...]

                                        Sort by: Top comments (filter)

                                        ────────────────────────────

                                        👤 John
                                        This video was really helpful!

                                        👍 245    👎    Reply

                                        12 replies
                                        └── Show replies

                                        ────────────────────────────

                                        👤 Sarah
                                        Great explanation!

                                        👍 120    👎    Reply

                                        ────────────────────────────

                                                Load more

3. Component Architecture:
--------------------------
    I'd break the feature into smaller components:
                                                Comments
                                                │
                                                ├── CommentsHeader
                                                │   ├── CommentCount
                                                │   └── SortDropdown
                                                │
                                                ├── CommentInput
                                                │
                                                ├── CommentList
                                                │   │
                                                │   ├── CommentItem
                                                │   │   ├── CommentAuthor
                                                │   │   ├── CommentContent
                                                │   │   ├── CommentActions
                                                │   │   │   ├── LikeButton
                                                │   │   │   ├── DislikeButton
                                                │   │   │   └── ReplyButton
                                                │   │   │
                                                │   │   └── ReplyList
                                                │   │       └── CommentItem
                                                │   │
                                                │   └── LoadingSkeleton
                                                │
                                                └── LoadMore     

    The important principle is: Keep the CommentItem reusable and keep comment-specific logic isolated from the parent.         

4. Data Model:
--------------
    A comment could look like:
        {
            id: "comment_123",
            videoId: "video_456",

            author: {
                id: "user_1",
                name: "John",
                avatar: "..."
            },

            text: "This video was really helpful!",

            likes: 245,
            dislikes: 4,

            userReaction: "like",

            replyCount: 12,

            createdAt: "2026-09-01T10:30:00Z"
        }                              

    For replies:
        {
            id: "reply_123",
            parentId: "comment_123",
            ...
        } 

    I prefer having a parentId rather than putting the entire reply tree inside every comment.

5. API Design:
--------------
    We might have APIs like:

        GET    /videos/:videoId/comments
        GET    /comments/:commentId/replies

        POST   /videos/:videoId/comments

        POST   /comments/:commentId/replies

        PATCH  /comments/:commentId

        DELETE /comments/:commentId

        POST   /comments/:commentId/like

        DELETE /comments/:commentId/like

        For pagination:
            GET /videos/123/comments?sort=top&cursor=abc123&limit=20


        Important:
            I'd prefer cursor-based pagination over offset pagination.

        Why?
            With thousands of comments, offset pagination can become problematic when new comments are inserted.

        Instead of: ?page=5

        we use: ?cursor=abc123

        The backend tells us the cursor for the next batch.
