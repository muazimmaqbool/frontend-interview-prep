******************** Design WhatsApp Chat UI *******************************

1. Start by clarifying the requirements:
----------------------------------------
    Functional requirements
            Users should be able to:
                - View a list of chats
                - Open a conversation
                - Send messages
                - Receive messages in real time
                - Send images/files
                - See typing indicators
                - See online/offline status
                - See message status
                - Sending
                - Sent
                - Delivered
                - Read
                - Load older messages
                - Search chats
                - Receive notifications

4. The Data Flow:
-----------------
    This is probably the most important diagram to understand.
                            OPEN CHAT
                               │
                               ▼
                        ┌──────────────┐
                        │ GET Messages │
                        └──────┬───────┘
                               │
                               ▼
                        ┌──────────┐
                        │ REST API │
                        └────┬─────┘
                             │
                             ▼
                        Initial Messages
                             │
                             ▼
                        ┌──────────────┐
                        │ Message List │
                        └──────────────┘
                --------------------------------

                    NEW MESSAGE ARRIVES
                            │
                            ▼
                        WebSocket
                            │
                            ▼
                        Update Cache
                            │
                            ▼
                        ┌──────────────┐
                        │ Message List │
                        └──────────────┘

        So the architecture is:
                        Initial Data → REST API
                        Live Data → WebSocket

5. How would I manage state?
----------------------------
    This is where many candidates make a mistake.
    They put everything into Redux.
    I would separate state into categories.

    -> A. Server State:
            Data coming from the backend:
                    Chats
                    Messages
                    Users
                    Online status
                    Message status

            Possible tools:
                    TanStack Query
                    Redux Toolkit Query

            For your stack, I would choose TanStack Query.

    -> B. UI State:
            Things that only control the interface:
                    Selected chat
                    Open attachment menu
                    Typing text
                    Emoji picker
                    Search input
                    Replying to message

            These can use:
                useState

            or a lightweight global store if multiple components need them.

    -> C. Real-Time State:
            Events from WebSocket:
                    NEW_MESSAGE
                    MESSAGE_DELIVERED
                    MESSAGE_READ
                    USER_TYPING
                    USER_ONLINE
                    USER_OFFLINE

            The WebSocket receives events and updates the existing cache/store.


6. Sending a Message:
---------------------
    Let's walk through the complete flow.

    Suppose I type: Hello 👋
                    and click send.

    -> A naive implementation would be:
                Click Send
                    ↓
                Wait for API
                    ↓
                Message appears

            That feels slow.

        Instead, use an optimistic update.

    -> Better flow:
            User clicks SEND
                    │
                    ▼
            Create Temporary Message
                    │
                    ▼
            Add Message to UI immediately
                    │
                    ▼
                API / Socket
                    │
                    ▼
                Server saves
                    │
                    ▼
            Replace Temporary ID
            with Real Message ID

    Visual example:
        You: Hello 👋          ⏳ Sending

        Then: 
            You: Hello 👋          ✓ Sent
