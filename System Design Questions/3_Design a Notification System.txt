Design a Notification System — Frontend System Design:

Assume the interviewer asks:
    Design a notification system for a large web application like LinkedIn, Facebook, or an EMR.

->For a frontend interview, focus on:
     how notifications reach the browser, 
     how they're stored/cached on the client, 
     unread counts, real-time updates, pagination, optimistic updates, and performance.


1. Clarify requirements:
------------------------
    I'd first establish that users should be able:
                     to receive notifications in real time, see an unread badge, open a notification panel, 
                     mark individual notifications as read, mark all as read, navigate to the relevant page, 
                     and load older notifications.

    Example:
                        🔔 3

              ┌────────────────────────┐
              │ Notifications          │
              │                        │
              │ ● John mentioned you   │
              │   2 min ago            │
              │                        │
              │ ● New appointment      │
              │   10 min ago           │
              │                        │
              │   Report completed     │
              │   Yesterday            │
              │                        │
              │      Load more         │
              └────────────────────────┘

    The important frontend requirements are real-time delivery, unread/read state, pagination, caching, deduplication, reconnection, and good performance

            <NotificationItem

4. Notification data model:
---------------------------
    A frontend notification could look like:
        {
            id: "notif_123",

            type: "COMMENT",

            title: "John replied to your comment",

            message: "Nice explanation!",

            isRead: false,

            createdAt: "2026-09-19T10:20:00Z",

            actor: {
                id: "user_22",
                name: "John",
                avatar: "..."
            },

            target: {
                type: "video",
                id: "video_123",
                url: "/videos/video_123"
            }
        }
    Having type is particularly useful.

    For example:
                COMMENT
                MESSAGE
                APPOINTMENT
                PAYMENT
                SYSTEM
                MENTION

    The UI can render each type differently.


5. Initial loading — REST API:
------------------------------
    When the application loads, we don't need to fetch 10,000 notifications.

    Use pagination: GET /notifications?limit=20
        Response:
            {
                notifications: [...],
                unreadCount: 7,
                nextCursor: "abc123"
            }

    Then: GET /notifications?cursor=abc123&limit=20

    I'd prefer cursor-based pagination.
    

6. TanStack Query:
------------------
    Notifications are server state, so TanStack Query is a good fit.

    const notificationsQuery = useInfiniteQuery({
        queryKey: ["notifications"],

        queryFn: ({ pageParam }) => fetchNotifications(pageParam),

        initialPageParam: null,

        getNextPageParam: (lastPage) =>
            lastPage.nextCursor ?? undefined
    });

    Now we get:
        Server
          ↓
        TanStack Query
          ↓
        Query Cache
          ↓
        NotificationPanel

    We don't need to copy all of that data into Redux.


7. Real-time notifications:
---------------------------
    This is the most important part of this system-design question.

    Imagine another user mentions me.
        User A
        │
        │ mentions User B
        ▼
     Backend
        │
        │ notification event
        ▼
      WebSocket
        │
        ▼
        User B's Browser

    Frontend listens for something like:
        socket.on("notification", (notification) => {
            ...
        });

    When a notification arrives, we update the query cache.
        Conceptually:
            queryClient.setQueryData(
                ["notifications"],
                oldData => {
                    // add notification to the beginning
                }
            );

    The UI immediately becomes: 🔔 3 to 🔔 4 without refreshing the page.
