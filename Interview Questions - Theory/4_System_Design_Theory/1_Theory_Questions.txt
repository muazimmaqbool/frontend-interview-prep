Part 1. Rendering & Delivery Models:
    These concepts help you decide where and when your application's HTML should be generated.

1. What is Static Site Generation (SSG), and how does it work?
Answer:
    SSG generates HTML pages at build time instead of generating them for every incoming request.

    The process:
        1. During the build, the framework fetches the required data.
        2. It generates HTML files for each route.
        3. These files are deployed to a CDN or hosting provider.
        4. When a user visits the page, the pre-generated HTML is delivered immediately.

    Advantages:
        - Very fast initial page delivery.
        - Excellent SEO because HTML is available immediately.
        - Easy to scale using CDN caching.
        - Less computation required per request.

    Disadvantages:
        - Content can become outdated.
        - Updating content may require rebuilding the site.

    Real-world example: Documentation websites, blogs and marketing websites.

    Que: Interview follow-up: What happens if the content changes after the build?
    Ans: You need to rebuild and redeploy the page, unless you use a mechanism such as ISR.


-----------------------------------------------------------------------------------------------------------------
2. What is Incremental Static Regeneration (ISR), and how is it different from SSG?
Answer:
    ISR allows statically generated pages to be regenerated after deployment without rebuilding the entire application.

    For example, consider an e-commerce product page.
        - Product description rarely changes.
        - Product price may change periodically.
        - Stock availability may change frequently.
    
    With ISR, you can configure a revalidation interval.

    When the page becomes stale, a visitor can trigger background regeneration. 
    The previously generated version can be served while the new version is generated.

    SSG	                                       ISR
    ---------------------------------------------------------------------------------------------
    Generated at build time	               |   Generated at build time and regenerated later
    Requires rebuild/redeploy to update	   |   Can update individual pages
    Suitable for mostly static content	   |   Suitable for periodically changing content

    ->Important: ISR does not automatically make every piece of data real-time. Frequently changing data may still need API requests.


----------------------------------------------------------------------------------------------------------------------
3. What is Server-Side Rendering (SSR)?
Answer:
    SSR generates HTML on the server for each incoming request.

    The process:
        1. User requests a page.
        2. Server receives the request.
        3. Server fetches the required data.
        4. Server generates HTML.
        5. Browser receives the rendered HTML.
        6. JavaScript hydrates the page to make it interactive.

    Advantages:
        - Fresh content on each request.
        - Better initial HTML availability for SEO.
        - Supports personalized content.
        - Useful for dynamic pages.

    Disadvantages:
        - More server computation.
        - Can increase response time under heavy traffic.
        - Requires careful caching and server resource management.

    Real-world examples: Personalized dashboards, user profiles and social media feeds.


----------------------------------------------------------------------------------------------------------------------
4. What is Client-Side Rendering (CSR)?
Answer:
    CSR means the browser handles most of the rendering work.

    The server initially sends a basic HTML document and JavaScript bundles. The browser executes JavaScript, fetches API data and builds the UI.

    For example, in a React application created using Vite:
        1. Browser requests the application.
        2. Server returns HTML and JavaScript assets.
        3. React initializes.
        4. Components render.
        5. API requests fetch application data.
        6. React updates the UI.

    Advantages:
        - Excellent interactivity.
        - Smooth navigation after initial loading.
        - Less server-side rendering computation.
        - Suitable for complex applications.

    Disadvantages:
        - Initial loading can be slower.
        - Large JavaScript bundles can affect performance.
        - SEO can require additional rendering strategies.

    Real-world examples: Figma-like editors, internal dashboards and complex SaaS applications.


----------------------------------------------------------------------------------------------------------------------
5. What is Hybrid Rendering? Why would you use it?
Answer:
    Hybrid rendering combines multiple rendering approaches within the same application.

    You don't have to choose only SSR, CSR or SSG for your entire application.

    For example, consider an e-commerce application:
        Page	            Rendering strategy	     Reason
        -----------------------------------------------------------------------
        Homepage	      | SSG	                  |  Mostly static content
        Product listing	  | SSG/ISR	              |  Cached catalog
        Product details	  | ISR	                  |  Periodically changing content
        User profile	  | SSR	                  |  Personalized content
        Shopping cart	  | CSR	                  |  Highly interactive

    Why use it?
        It allows you to optimize each route according to its requirements rather than applying one rendering strategy everywhere.


----------------------------------------------------------------------------------------------------------------------
6. What is a CDN, and how does Edge Delivery improve performance?
Answer:
    A Content Delivery Network (CDN) is a geographically distributed network of servers that stores cached copies of content.

    Without a CDN:
        A user in India might need to download assets from a server located in the US.

    With a CDN:
        The user can receive cached assets from a nearby CDN location.

    Edge delivery takes this further by allowing computation and, in some architectures, rendering to happen closer to users.

    Benefits:
        - Reduced network latency.
        - Faster asset delivery.
        - Reduced load on the origin server.
        - Better global scalability.

    Interview follow-up: Does a CDN cache everything?

    No. Static assets are commonly cached, while personalized or sensitive responses require carefully configured caching policies. 
        Incorrectly caching private responses can expose user data.

Part 2. Performance & Optimization:
    These concepts are particularly important when designing applications with large bundles, complex dashboards and thousands of records.

7. What are TTFB, FCP, LCP and CLS?
Answer:
    These are important frontend performance metrics.
    Metric	       Meaning	                    What it measures
    ------------------------------------------------------------------------------------
    TTF       Time to First Byte	         How quickly the server starts responding
    FCP	      First Contentful Paint	     When the first visible content appears
    LCP	      Largest Contentful Paint	     When the largest visible content element appears
    CLS	      Cumulative Layout Shift	     Unexpected movement of page elements

    Example:
        Imagine opening a dashboard:
            - TTFB: Browser receives the first response bytes.
            - FCP: Header or loading indicator appears.
            - LCP: Main dashboard chart becomes visible.
            - CLS: The chart suddenly shifts downward because its container had no reserved height.
            
        How do you improve them?
            - TTFB: Improve server response time, CDN usage and caching.
            - FCP: Reduce render-blocking resources.
            - LCP: Optimize hero images, fonts and critical resources.
            - CLS: Reserve image dimensions and avoid injecting unexpected content.
