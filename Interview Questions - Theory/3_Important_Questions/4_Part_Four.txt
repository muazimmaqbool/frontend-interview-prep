Question 1: What is the difference between React.createElement and JSX under the hood?
Answer:
    JSX is syntax sugar for React.createElement (in the classic JSX transform). 
    Both ultimately create a React element object that React uses to build the UI.
                or
    Under the hood, JSX is purely syntactic sugar for function calls that create React elements; browsers cannot read JSX directly.
    When you write JSX, a compiler toolchain like Babel transforms that markup into plain JavaScript objects. 
    In older versions of React, JSX compiled directly into React.createElement()
    In modern React (React 17+), it compiles into automatic runtime functions imported from react/jsx-runtime

    ->JSX:
        const element = <h1>Hello</h1>;

        is roughly transformed into:

            const element = React.createElement(
            "h1",
            null,
            "Hello"
        );

    ->With props:
        const element = <button className="btn">Click</button>;

        roughly becomes:

        const element = React.createElement(
            "button",
            { className: "btn" },
            "Click"
        );

    ->Interview one-liner:
        JSX is a developer-friendly syntax that gets compiled into React element creation calls; traditionally React.createElement, 
        while modern React can use the newer JSX runtime.

Question 2: What is the difference between a Higher Order Component and a custom hook?
Answer:
    Both are used for reusing logic, but they work differently.

    ->Higher-Order Component (HOC):
        A function that takes a component and returns an enhanced component.
        Example:
            const withAuth = (Component) => {
                                return (props) => {
                                    return isLoggedIn
                                    ? <Component {...props} />
                                    : <Login />;
                                };
                            };
            Usage: export default withAuth(Dashboard);

    ->Custom Hook:
        A function that reuses stateful React logic between components.
        Example:
            const useAuth = () => {
                const [isLoggedIn, setIsLoggedIn] = useState(false);
                ......
                ......
                return { isLoggedIn, setIsLoggedIn };
            };

            Usage: const { isLoggedIn } = useAuth();

    ->Key Difference:
        | HOC                        | Custom Hook               |
        | -------------------------- | ------------------------- |
        | Enhances/wraps a component | Reuses logic              |
        | Returns a component        | Returns values/functions  |
        | Can cause wrapper/nesting  | Usually simpler           |
        | Older pattern              | Preferred in modern React |

Question 3: What is the difference between useTransition and useDeferredValue?
Answer:
    Both are used to keep the UI responsive, but they work differently.

    ->useTransition → Marks a state update as low priority.
        startTransition(() => {
            setResults(data);
        });

    ->useDeferredValue → Creates a delayed version of an existing value.
        const deferredSearch = useDeferredValue(search);

    ->Key Difference:
        | `useTransition`                    | `useDeferredValue`                |
        | ---------------------------------- | --------------------------------- |
        | Controls **how an update happens** | Controls **when a value is used** |
        | You wrap the state update          | You pass it a value               |
        | Gives `isPending`                  | Doesn't give `isPending`          |

    ->Interview one-liner:
        Use useTransition when you control the state update; use useDeferredValue when you already have a value and want React to defer its expensive usage.

Question 4; How does React handle hydration of server rendered components with async data?
Answer:
    With async data, React first receives server-rendered HTML so the user can see the UI quickly. 
    On the client, React hydrates that HTML and connects it to the React component tree. 
    If data is still loading, React can use Suspense to show a fallback and hydrate parts of the page as their data becomes available

    ->Simple flow:
            Server
                ↓
            Fetch async data
                ↓
            Render HTML
                ↓
            Browser receives HTML
                ↓
            React hydrates
                ↓
            Async data/component becomes ready
                ↓
            UI becomes interactive

Question 5: What are Generator Functions?
Answer:
    Generator functions are special JavaScript functions that can pause execution and resume later. They are defined using function* and use the yield keyword.
    Example:
        function* numbers() {
            yield 1;
            yield 2;
            yield 3;
        }

        const generator = numbers();

        console.log(generator.next()); // { value: 1, done: false }
        console.log(generator.next()); // { value: 2, done: false }
        console.log(generator.next()); // { value: 3, done: false }
        console.log(generator.next()); // { value: undefined, done: true}

        ->How it works:
            function* 
                ↓
            yield 1 → pause
                ↓
            next() → resume
                ↓
            yield 2 → pause
                ↓
            next() → resume

        ->Key point: yield pauses the function, and next() resumes it.

        ->Common Uses:
            Iterators
            Lazy evaluation
            Processing large data sets
            Async workflows (historically, before async/await became common)

        ->Interview one-liner:
            A generator is a function that can pause and resume its execution using yield and next().

Question 6: Difference between map(), filter(), reduce(), and forEach()?
Answer:
    All four are array methods, but they serve different purposes:

        | Method      | Purpose                            | Returns      |
        | ----------- | ---------------------------------- | ------------ |
        | `map()`     | Transform every element            | New array    |
        | `filter()`  | Select elements based on condition | New array    |
        | `reduce()`  | Combine elements into one result   | Single value |
        | `forEach()` | Execute code for each element      | `undefined`  |
    
    1. map() → Transform:
                    const numbers = [1, 2, 3];
                    const result = numbers.map((num) => num * 2);
                    console.log(result); // [2, 4, 6]

                    Use when you want to change/transform every element.

    2. filter() → Select:
                    const numbers = [1, 2, 3, 4];
                    const result = numbers.filter((num) => num > 2);
                    console.log(result); // [3, 4]

                    Use when you want to keep only elements that satisfy a condition.

    3. reduce() → Accumulate:
                    const numbers = [1, 2, 3, 4];
                    const result = numbers.reduce((total, num) => {
                        return total + num;
                    }, 0);
                    console.log(result); // 10

                    Use when you want to combine an array into a single result.

    4. forEach() → Perform an action
                    const numbers = [1, 2, 3];
                    numbers.forEach((num) => {
                        console.log(num);
                    });

                    Use when you simply want to perform an operation for each element.

    Easy way to remember:
        map     → Change
        filter  → Select
        reduce  → Combine
        forEach → Do something

Question 7: If an API is giving a slow response, how do you debug what the problem is?
Answer:
    First, I check the Network tab in DevTools to see where the time is being spent. 
    I look at DNS, connection, TTFB, response/download time, request payload, and response size.

    Then I determine whether the problem is:
        Frontend → unnecessary API calls, large payload processing, duplicate requests.
        Backend → slow database query, heavy business logic, server performance.
        Network → latency, large response, connection issues.

    I also check backend/server logs and database query performance to identify the bottleneck.

    Interview one-liner:
        I first measure the request in the Network tab, identify whether the delay is frontend, network, or backend, 
        and then use server logs and database metrics to find the exact bottleneck.

Question 8: what is the difference between for-in and for-of loop?
Answer:
    for...in vs for...of
    
    ->for...in → keys/properties
        Used mainly for objects.

        const user = {
            name: "Muazim",
            age: 25
        };

        for (const key in user) {
            console.log(key);
        }

        Output:
        name
        age

    ->for...of → values
        Used with iterable objects like arrays, strings, Maps, Sets, etc.       

        const numbers = [10, 20, 30];

        for (const value of numbers) {
            console.log(value);
        }

        Output:
            10
            20
            30

    ->Easy way to remember:
        for...in  → keys
        for...of  → values
